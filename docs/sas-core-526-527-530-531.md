# SAS core additions: #526, #527, #530, #531

These additions retain the v1 attestation record and the original ATTESTED event shape.

## #526: Payload-size fee policy

The existing admin-controlled set_fee(token, base) still defines the payment token. To opt into dynamic charges, call set_fee_per_byte(rate), where rate is a non-negative i128 amount in token base units for each data byte. quote_attestation_fee(schema_uid, data_len) computes base + rate * data_len, with checked arithmetic and the existing 10,000-byte payload cap. set_schema_zero_fee(schema_uid, true) sets an explicit exemption. clear_fee() clears both the base and per-byte charge.

When a positive per-byte rate is active, unpaid issuance entrypoints reject non-exempt attestations with InsufficientFee; use attest_with_value with the quoted exact amount. Underpayments on the new dynamic path return InsufficientFee; incorrect token and overpayment return FeeMismatch. A fee-aware ATTFEE event follows the original ATTESTED event, retaining the original wire schema for pre-existing consumers. The fee quote uses constant work with respect to input size.

## #527: Delegation scope

The root attester can set_delegation_policy(attester, policy) with authorized_schema_uid = Only(uid) for a single schema, or Any for a wildcard; permissions bit 1 allows issuance and valid_until = 0 disables expiry. This policy also restricts existing v1 delegated issuance, so an old signature cannot bypass an active schema restriction.

New attest_by_scoped_delegation takes a DelegationAuthorization struct containing a signed scope, permission mask and expiry. hash_scoped_attestation in soroban-sas-common and sign_scoped_attestation in the Rust SDK reproduce the matching domain-separated digest. Nonces remain strictly increasing per attester. The v1 sign-and-submit flow is retained.

## #530: Protocol circuit breaker

Admin-authorized pause/unpause controls mutations, including bulk_reindex and reindex_attestation, while get_attestation and verify_attestation stay callable. Blocked paths return ProtocolPaused. Additional PRTPAUSED and PRTUNPAUS events include the ledger timestamp and authorizer while preserving legacy PAUSED and UNPAUSED events. Admin handover already uses propose_admin/accept_admin.

## #531: ZK verification integration and security boundary

The admin must set_zk_verifier to the address of a genuinely cryptographic verifier contract exposing verify_proof(proof: Bytes, public_inputs: Vec<BytesN<32>>) -> bool. SAS passes public inputs in the fixed order [attestation UID, schema UID, nullifier], rejects missing/failed verifier calls, and records consumed nullifiers only after successful issuance in the same transaction. Proof bytes cannot be empty or exceed 4 KiB.

IMPORTANT: The current contracts/zk-verifier proof-prefix checker is not an actual zk-SNARK verifier and MUST NOT be connected to this API as proof of cryptographic validity. The new integration tests exercise the adapter with a deliberate mock, not a real Groth16 or UltraPlonk proof. A production deployment requires a trusted on-chain verification-key implementation and an independently verified circuit whose public-input order matches this ABI. A full sample-circuit cryptographic E2E test remains outstanding.

Because these are new contract entrypoints, deployments require a reviewed WASM upgrade with the project's existing versioning and admin procedures. Run cargo fmt --all -- --check, cargo clippy --workspace --all-targets -- -D warnings, and cargo test --workspace before merging.
